- 保留工作区中已经存在的文章改动。

- 不扩展到同步对象、设备驱动或应用模块等后续文章主题。

## 内容设计

### 可构建示例

文章增加最小应用目录、`CMakeLists.txt`、`prj.conf`、`src/main.c`、构建命令和参考输出。静态线程示例使用完整源文件，并通过线程入口的 `p1` 参数传入只读配置，演示入口参数的实际用途。

动态创建章节给出可独立理解的完整代码，包含线程栈、控制块、入口函数、延迟启动、线程命名、重复创建保护、错误检查和可观察日志。代码明确区分 `K_THREAD_DEFINE` 的毫秒整数延迟与 `k_thread_create()` 的 `k_timeout_t` 延迟。

### 注释与接口说明

所有文章自定义函数使用简洁的 Doxygen 风格注释，说明职责、入口参数及约束。首次出现下列接口时提供签名、逐项参数说明、返回值或展开结果以及常见陷阱：

- `K_THREAD_DEFINE`
- `K_THREAD_STACK_DEFINE`
- `K_THREAD_STACK_SIZEOF`
- `k_thread_create`
- `k_thread_name_set`
- `k_thread_start`
- `k_sleep`

宏按宏说明，不错误地称为函数。参数表重点解释线程入口的 `p1`、`p2`、`p3`、优先级方向、`options` 和启动延迟。

### 栈分析

栈章节加入 Thread Analyzer 的开发期 Kconfig、调用方式、典型输出和解读方法。文章说明测量只能覆盖已经执行的路径，并要求覆盖 BLE、错误日志、OTA 和恢复流程等峰值路径后再确定余量。

### 技术校正

对照 Zephyr 4.4 官方 Threads、Scheduling、Thread APIs、Thread Stack APIs 和 Thread Analyzer 文档核对以下内容：

- 协作与抢占优先级的边界及数值方向。
- 静态与动态线程启动延迟的类型和单位。
- 线程栈必须使用专用宏以及不能用裸 `sizeof` 代替 `K_THREAD_STACK_SIZEOF`。
- 线程命名依赖的配置和错误返回。
- `k_thread_start` 的适用条件与兼容性说明。
